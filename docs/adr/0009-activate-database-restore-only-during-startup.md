# Database Restore activates only during startup

An administrator may stage one exact retained Database Backup Operation while the server is running, but Civic never replaces an open authoritative SQLite database. The staged manifest is activated only on the next server startup, before the runtime database is opened. Startup revalidates the source file against its persisted size, SHA-256, world/dependency identity, and current schema; creates a validated rollback snapshot of the closed current database; prepares a candidate containing a durable activation token; and then atomically moves the closed files. A staged source is pinned outside normal backup rotation until cancellation or activation.

Online replacement would make existing JDBC state authoritative over a different file and could split in-memory services from persistence. A simple file copy at shutdown would leave ambiguous crash windows around the current/candidate rename. The external phase manifest, candidate activation token, and preserved previous-file window make restart recovery deterministic, while immutable `STAGED`, `FAILED`, `CANCELLED`, and `ACTIVATED` audit evidence records operator intent and outcomes. This restores only Civic SQLite: Lightman's Currency accounts and transaction markers remain in world `SavedData`, so production recovery still requires an intentionally matched full-world backup and must not use an isolated SQLite rollback as if it were a cross-store transaction.
